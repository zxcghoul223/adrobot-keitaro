# Adrobot — обёртка над Keitaro

Тестовое приложение на **FastAPI + SQLAlchemy 2 + Alembic**, интерфейс — HTML, CSS и JavaScript без сборщика и внешних CDN.

Создаёт кампанию с доменом, группой, источником и двумя последовательными потоками: выбранная страна → Google; остальные посетители → выбранный оффер. Редактор сохраняет изменения в локальный черновик и публикует их в Keitaro отдельной кнопкой.

## Требования

- Python **3.12+**.
- Для live-режима: HTTPS-адрес Keitaro и существующий Admin API key с доступом к нужным кампаниям, офферам, доменам, группам и источникам.
- Node.js, Docker и отдельный сервер БД для запуска не нужны. По умолчанию используется SQLite.

Все команды выполняются из корня проекта.

## Быстрый запуск: Windows / PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Активация окружения не требуется: команды явно используют Python из `.venv`.

## Быстрый запуск: Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python -m alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Откройте [интерфейс](http://127.0.0.1:8000), [Swagger UI](http://127.0.0.1:8000/docs) или [проверку работоспособности](http://127.0.0.1:8000/healthz).

Скопированный `.env.example` включает **`APP_MODE=demo`**. Это явно обозначенная автономная песочница с четырьмя демонстрационными офферами. Её кампании и черновики сохраняются в SQLite, запросы в реальный Keitaro не отправляются. При первом запуске список кампаний пуст — создайте свою через форму.

## Подключение к Keitaro

Остановите сервер и укажите в локальном `.env`:

```dotenv
APP_MODE=live
DATABASE_URL=sqlite:///./adrobot-live.db
CAMPAIGN_PREFIX=test_Dyachkov_
KEITARO_URL=https://your-tracker.example
KEITARO_API_KEY=replace-with-your-existing-api-key
REQUEST_TIMEOUT=20
```

`KEITARO_URL` — только HTTPS-origin, без `/admin`, `/admin_api/v1`, логина, query-параметров и завершающих путей. API-ключ берётся в профиле Keitaro, в разделе API-ключей. Приложение передаёт его сервером в заголовке `Api-Key`; ключ не попадает в браузер.

`CAMPAIGN_PREFIX` имеет формат `test_Surname_`. Префикс автоматически добавляется к названию новой кампании, если его ещё нет. В список и редактор допускаются только кампании с этим префиксом. Это ограничение области тестовых изменений, а не система авторизации.

После смены `DATABASE_URL` снова выполните `python -m alembic upgrade head` выбранным Python из окружения и перезапустите сервер. Не подменяйте `.env` во время работающего процесса. В режиме live интерфейс явно показывает подключение к реальному Keitaro.

`.env`, локальные БД и журналы исключены из Git. В репозиторий включён только шаблон настроек.

## Миграции

Схема создаётся и обновляется через Alembic; приложение не вызывает `create_all` при запуске. Если миграция не применена, запуск завершится с объяснением.

```bash
python -m alembic upgrade head
python -m alembic current
python -m alembic check
```

На Windows без активации замените `python` на `.\.venv\Scripts\python.exe`. `current` показывает применённую ревизию, `check` проверяет соответствие схемы SQLAlchemy-моделям.

## Проверка сценариев из ТЗ

1. **Создать кампанию.** Введите название, GEO (`AU`, `MX`, `RO` и другие существующие ISO-коды), выберите оффер через поиск по ID/названию, домен, группу и источник. Результат — кампания и два потока в порядке проверки: GEO → Google, затем офферы.
2. **Fetch streams.** Откройте кампанию в редакторе. Кнопка загружает актуальное состояние из трекера. Потоки без офферов видны, но доступны только для просмотра: редактор не меняет их фильтры и редиректы.
3. **Черновик.** Добавьте оффер. Свободные доли пересчитаются, поток выделится как неопубликованный. Изменения уже сохранены в локальной БД и переживают обновление страницы, но ещё не отправлены в Keitaro.
4. **Push to Keitaro.** Публикует состав офферов выбранного потока. Остальные настройки потока и другие потоки не перезаписываются.
5. **Cancel.** Восстанавливает последнее опубликованное состояние выбранного потока. Новые неопубликованные привязки офферов исчезают из черновика.
6. **Remove / Bring back.** Удалённый оффер остаётся серым в локальном архиве с долей 0%. После Push он исчезает из потока Keitaro; Bring back возвращает его в черновик, повторный Push — в Keitaro. Сам оффер в глобальном каталоге не удаляется.
7. **Закрепление доли.** Для потока из четырёх офферов закрепите один на 25%, затем удалите один из остальных. Закреплённый сохранит 25%, два свободных получат 38% и 37% — ближайшее целочисленное распределение остатка 75%. После Cancel возвращаются и состав, и закрепления опубликованной версии.
8. **Внешнее изменение.** Если оффер удалён непосредственно из потока Keitaro, Fetch streams переводит известную локальную привязку в removed/архив, сохраняя возможность Bring back. При наличии черновика интерфейс сначала запрашивает подтверждение его замены.

Доли и закрепления — **целые проценты от 0 до 100**, сумма активных долей — 100%. Сначала резервируются закреплённые проценты, затем остаток делится поровну между свободными офферами. Оставшиеся единичные проценты получают офферы с меньшими ID: например, три равных доли — 34%, 33%, 33%. Превышение 100% отклоняется.

Видеопример математически даёт 25% + 37,5% + 37,5%. Предоставленная версия Keitaro API принимает только целочисленные `share` не больше 100: в проверке на собственной тестовой кампании значения `37.5` и `10000` отклонены с HTTP 422 (`Share must be an integer` и `Share must be no more than 100`). Поэтому приложение показывает и отправляет одинаковые целые проценты 25% + 38% + 37%; масштабирование процентов в большие относительные веса не используется.

## Устройство проекта

| Файл / каталог | Назначение |
|---|---|
| `app/main.py` | FastAPI-маршруты, интерфейс, обработка ошибок и lifecycle |
| `app/services.py` | Создание кампаний, черновики, синхронизация и публикация |
| `app/keitaro.py` | Асинхронный HTTP-клиент Admin API |
| `app/weights.py` | Перераспределение долей с закреплениями |
| `app/models.py` | SQLAlchemy-модели состояния, операций и демо-данных |
| `app/demo.py` | Автономный демонстрационный трекер |
| `app/templates/`, `app/static/` | Интерфейс без отдельной сборки |
| `migrations/`, `tests/` | Миграции и автоматические проверки |

В `campaign_states` хранится JSON-снимок потоков: опубликованный состав, текущий черновик, архив и закрепления. SQLAlchemy используется для реального постоянного хранения. `operations` фиксирует создание и публикацию, включая операции с неопределённым результатом. `demo_campaigns` хранит состояние демонстрационного трекера отдельно от рабочих снимков. Для demo и live снимки разделены также полем `mode`.

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check .
```

На Windows без активации используйте `.\.venv\Scripts\python.exe`. Тесты выполняются на изолированных БД и подменённом HTTP-транспорте; реальные кампании не изменяются. Для интеграции с настоящим трекером используйте live-режим и собственный тестовый префикс.

## Проверка реального трекера

На предоставленном Keitaro создана собственная тестовая кампания: проверены создание двух потоков, фильтр страны, Google-редирект, основной оффер и выбранные домен, группа и источник. Загрузка потоков, сохранение закрепления в черновик и публикация с повторным чтением результата также проверены на живом API — на новой и существующей кампаниях.

Учётной записи доступен один оффер. Создание дополнительных офферов отклоняется с HTTP 403 из-за прав доступа. Поэтому полный сценарий с несколькими разными офферами — добавление, удаление, Bring back и закрепления — проверяется в автономном демо и автоматических тестах. Сквозная live-проверка этого сценария требует дополнительных доступных офферов.

## Ошибки и ограничения

- Кампания создаётся выключенной и включается после создания обоих потоков. При известном ID и ошибке настройки приложение пытается архивировать неполную кампанию. Если результат запроса неизвестен, нужно проверить Keitaro перед повторным созданием; автоматических повторов изменяющих запросов нет.
- Перед Push сравнивается снимок конфигурации Keitaro, а локальные изменения защищены ревизией от устаревшей вкладки. Проверка внешнего состояния не атомарна с записью в Keitaro: изменение напрямую в трекере между проверкой и PUT всё ещё возможно.
- Используйте **один Uvicorn worker**: блокировки операций действуют внутри процесса. Многопроцессный запуск требует межпроцессной синхронизации.
- Последний активный оффер удалить нельзя, чтобы не оставлять поток без назначения. Поддерживается до 100 активных офферов в потоке.
- `REQUEST_TIMEOUT` задаёт таймаут отдельных сетевых операций HTTPX, а не общий предел времени создания кампании. Ошибки доступа, лимитов и сети показываются в интерфейсе.
- Пользовательская авторизация не реализована: приложение предназначено для локальной проверки на `127.0.0.1`. Для общего доступа потребуется отдельная аутентификация.

## Использование ИИ-агентов

Codex использовался для реализации и интеграции бэкенда, миграций, интерфейса, тестов и документации. Требования редактора сверялись с видео: черновик/Push/Cancel, архив/Bring back, внешние удаления и закреплённые доли.
